# LoyalTools

A Blender add-on for creating mods for **Arknights: Endfield**.

LoyalTools is based on **TheHerta4** and integrates the Frame Analysis parsing capabilities of **EFMI-Tools**. It provides an end-to-end workflow from **model extraction → editing → texture marking → mod export**, without requiring SSMT4.

- Panel location: Blender 3D Viewport → Sidebar (`N`) → `LoyalTools`
- Required Blender version: 4.5+

## Installation

1. Open [GitHub Releases](https://github.com/loyal37/loyaltools/releases) and download the attached file named `LoyalTools-vX.Y.Z-Blender.zip`.
2. Do not extract the archive. In Blender, open **Edit → Preferences → Add-ons**, choose **Install from Disk**, and select the ZIP file.
3. Enable `LoyalTools` after installation.

> Do not install GitHub's automatically generated `Source code (zip)` archive. Its top-level directory looks like `loyaltools-1.6.1/` and contains a hyphen and version number, so Blender cannot import it as a Python add-on module.

## Differences from TheHerta4

| Feature | TheHerta4 | LoyalTools |
|---|---|---|
| Model extraction | Requires the external SSMT4 application | Includes a DrawIB extraction panel that reads Frame Analysis dumps directly |
| Texture marking | Performed in SSMT4 | Built into Blender |
| Game presets | Loaded from SSMT4 configuration | Selectable in standalone mode, with EFMI/Endfield as the default; existing SSMT4 installations remain supported |
| Workspace | Managed by SSMT4 | Any custom directory can be used; synchronization with SSMT4 is also supported when available |
| Blueprint export and toolkit | Supported | Fully retained |
| EFMI Merged Skeleton | Requires an external workflow | Includes standalone extraction, import, and LOD mapping; the Cross IB node can switch between standard Cross IB and Merged Skeleton modes |

## Prerequisites

1. The game must have the **EFMI runtime framework** installed. This is the framework that provides `CommandList\EFMIv1\OverrideTextures`, normally deployed by the EFMI Importer in XXMI or by SSMT4. Standard mods depend on this command list, while Merged Skeleton mods require **EFMI 1.4.1 or later**.
2. Frame Analysis dumps must be generated by 3dmigoto, normally by pressing `F8` in game. The recommended `d3dx.ini` analysis options are:

   ```ini
   analyse_options = deferred_ctx_immediate dump_rt dump_cb dump_vb dump_ib dump_tex buf txt dds symlink
   ```

   The extractor expects the dump to contain `log.txt`, a `deduped/` directory, `.buf` and `.txt` files for each VB/IB, and texture `.dds` files.

## Workflow

### 1. Configure a workspace in standalone mode

In the **Basic Information** panel, set the workspace source to **Custom Directory** and select any empty directory.

When SSMT4 is not detected, the panel displays a standalone-mode notice and defaults to the EFMI/Endfield preset. If SSMT4 is installed but you still want to use LoyalTools presets, enable the option that forces standalone presets.

### 2. Extract models

In the DrawIB extraction panel:

1. Select the **Frame Analysis dump directory** (`FrameAnalysis-*`).
2. Add one or more eight-digit hexadecimal **DrawIB** values to the table. Aliases are optional.
3. Run **Extract**. LoyalTools copies candidate textures, imports the meshes, and connects them to a blueprint automatically.
4. Results are written to the workspace under `workplace/<DrawIB>-<IndexCount>-<FirstIndex>/TYPE_GPU-EFMI/`, which remains compatible with the SSMT4 directory structure. Imported objects use the name `DrawIB-IndexCount-FirstIndex`; their collection uses the custom workspace name and a red color tag.

### 3. Mark textures

In the texture-marking panel:

1. Select an imported model and refresh the texture list.
2. Review the candidate textures extracted for that DrawIB, including their `ps-t` slots and hashes.
3. Choose a mark name such as `DiffuseMap`, `NormalMap`, `LightMap`, or a custom name, then choose a marking method:
   - **Slot-based**: binds the texture directly to a `ps-t` slot in the INI file. This is recommended.
   - **Hash-based**: generates an independent `TextureOverride` for the texture hash.
4. Mark the selected texture. LoyalTools copies it as `<DrawIB>-<IndexCount>-<FirstIndex>-<MarkName>.dds`, stores the mark in the submesh JSON, and generates the texture INI and file copy during export.
5. Use texture preview or open the texture directory when identifying candidates.

### 3.5. Merged Skeleton workflow

Merged Skeleton support does not change the standard DrawIB workflow. Switch the workflow mode in the extraction panel to **Merged Skeleton**:

1. Select a Frame Analysis dump captured while the full-detail character is visible. No DrawIB input is required.
2. Run extraction. LoyalTools applies the EFMI-Tools v0.6.2 character/component rules, reads each component's bone matrices, and creates a global vertex-group mapping. A character may contain both explicitly and implicitly weighted components. For implicit components, the first bone receives a weight of `1.0` on each vertex, matching EFMI behavior. Geometry is rebuilt from the original Frame Analysis IB ranges rather than from the rebased in-memory indices used during EFMI character detection.
3. Output directories and object names still use `<IBHash>-<IndexCount>-<FirstIndex>`. The workspace root also receives `EFMI_MergedSkeleton.json`, which records the full-detail source frame.
4. To add an LOD, move the character far enough away in game to switch to its lower-detail model and capture another frame. Keep the primary Frame Analysis directory set to the original full-detail frame, select the distant frame in the LOD Frame Analysis field, and run the LOD mapping operation. LoyalTools matches characters and components using the EFMI-Tools v0.6.2 rules and writes the LOD IB, index count, local bone remap, and VB layouts into the profile. Additional frames can add more LOD levels, while remapping the same object updates its existing entry.
5. Importing the main Merged Skeleton model converts each component's local vertex groups to the profile's global groups. Every object receives the same `0..bones_count-1` vertex-group space; empty groups preserve the direct relationship between Blender group indices and global bone IDs. Standard imports do not apply this mapping. Real LOD meshes can be imported separately into isolated yellow preview collections and never enter the export blueprint.
6. No extra node is required when Cross IB mapping is not used: the generated blueprint and object metadata select Merged Skeleton export automatically. When Cross IB mapping is required, add a Cross IB node, switch its routing mode to **Merged Skeleton**, and enter the usual `source IndexCount >> target IndexCount` mapping. The VS 200–204 options are not used in this mode.
7. Merged Skeleton components do not require manual Diffuse, Light, or Normal marks. Extraction uses EFMI-Tools component-level texture ownership and filtering rules, skipping JPG/BUF resources, files smaller than 256 KB, and non-square textures. It prepares `<unique_str>-DiffuseMap/LightMap/NormalMap.dds` independently for each IB. Identical texture content is intentionally not deduplicated across IBs, so every component can be edited independently. The standard workflow continues to use manual texture marks.
8. Generate the mod. LoyalTools copies the component textures into `Textures/`, creates component-specific `ps-t` bindings, exports 16-bit `BLENDINDICES`, and emits EFMI 1.4.1 Merged Skeleton callbacks and component entry points. It does not generate EFMI-Tools global texture-hash overrides or the HLSL used by standard Cross IB routing. When LOD mappings exist, the INI adds `$lod_level` detection, emits `<unique_str>-<Category>-LOD<n>.buf` only for slots whose layouts differ, and creates R16 `BlendRemap` resources only when needed. An LOD that shares the full-detail IB does not receive a duplicate hash entry point.

Starting with v1.6.1, export restores bones owned by the current component—but deduplicated across components in Blender—to that component's private bone range. This keeps LOD capture and mesh reads on the same indices. Vertex groups not provided by the current component keep their original IDs, preserving genuine Cross IB weights.

All GPU-posed components in the profile keep their entry points and Merged Skeleton callbacks. A GPU component removed from the blueprint can still provide shared bones to other components, but it binds no mesh or texture and emits no draw call, so it remains hidden. A real `cpu_posed = true` component is controlled by blueprint connectivity: when disconnected, it generates no entry point, callback, texture, or buffer; when connected, it uses a `gpu_posed = 0` entry point, automatic textures, and `drawindexed = INDEX_COUNT, FIRST_INDEX, 0` to render the original game mesh. CPU-posed components never export custom IB/VB data and their Blender weights do not participate in merged skinning.

A single blueprint cannot mix standard Cross IB and Merged Skeleton routing. Global vertex-group IDs are limited to 65,535, while the original bone buffer of an individual game component remains limited to 256 entries.

### 4. Edit and export

Editing and export follow the original TheHerta4 workflow. Use the blueprint system or quick local export to generate a mod.

In standalone mode, when no game directory is configured, the mod is written to `<workspace>/GeneratedMod/`. Copy that output into the game's Mods directory.

## Notes

- **Do not enable LoyalTools and TheHerta4 at the same time.** They share many internal operator, panel, and node identifiers, which causes registration conflicts.
- Extraction is specific to Endfield/EFMI. Other game presets display a warning.
- v1.4.8 fixed incorrect VB starting offsets for shared-buffer Merged Skeleton components with `FirstIndex > 0`. Incorrect `.buf` or `.ib` files extracted with older versions cannot be repaired in place; extract and import them again from the original Frame Analysis dump.
- Starting with v1.4.10, a Merged Skeleton Cross IB segment binds only the source IB/VB and inherits the Diffuse, Light, and Normal textures already bound by the target component earlier in the same command list. Standard Cross IB behavior is unchanged.
- Starting with v1.5.0, Merged Skeleton profiles can add LOD mappings from independent distant Frame Analysis captures. Blender continues to edit only the full-detail model; export creates LOD entry points, required VB layout variants, and bone remaps automatically. Standard DrawIB and Cross IB workflows do not read the LOD profile.
- Starting with v1.5.1, one-to-one LOD assignment removes candidates below the component similarity threshold before solving. Extra LOD components and full-detail components without an independent LOD may remain unmatched instead of allowing weak matches to steal valid components. When a component has no independent LOD, the panel warns against using its global vertex-group range on other meshes.
- Starting with v1.6.0, the Merged Skeleton panel separates main-model import from LOD preview import. The main model can be imported repeatedly into new blueprints. Real LOD meshes enter isolated yellow preview collections, never connect to an export blueprint, and can be inspected through an `LOD unique_str → main unique_str` mapping table.
- Starting with v1.6.1, Merged Skeleton export restores vertex groups owned by the current component to its private pool before writing Blend buffers. This fixes incorrect bone-matrix reads even when the LOD mapping is geometrically correct. Standard exports, Blender vertex groups, and genuine Cross IB weights are unchanged. Existing `.blend` files do not need to be re-extracted or re-imported; regenerate the mod with the new version.
- Starting with v1.6.2, the Merged Skeleton extraction panel uses concise `LOD0` and `LOD1` path labels and removes redundant workflow guidance. Extraction, import, mapping, and export behavior are unchanged.
- CPU-posed components support only original-game-mesh rendering and texture replacement. They cannot export custom geometry or weights, and their overrides are generated only when the object is connected to the blueprint.
- The updater points to `https://github.com/loyal37/loyaltools` and checks this repository's Releases for new versions.
